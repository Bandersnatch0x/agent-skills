# Target User and JTBD

Purpose: before positioning or feature cuts, pin down the real users and their jobs from evidence — kill imaginary audiences.

## Inputs
- Repo / product name; existing README, feedback, issues, chat logs; known competitors or alternatives.

## Steps
1. **Candidate personas**: list 3–5 plausible user types (role + scenario), each with one line on why they would open this product.
2. **Filter by evidence**: label each type strong / weak / pure guess — evidence must point to a file, issue, conversation, or data; anything else is a guess.
3. **Pick the primary**: keep exactly 1 primary user + at most 1 secondary; everyone else goes on the "not serving yet" list.
4. **JTBD list**: for the primary user write ≤5 jobs, each with trigger scenario, current alternative, success criterion, cost of failure.
5. **Anti-users**: 3 personas that look like users but are not, with the reason each fails.
6. **Validation slice**: the smallest check runnable next week (5 interview questions, or 1–2 observable metrics).

## Output
- One paragraph each for the primary and secondary user
- JTBD table
- Anti-user list
- Validation slice
- "Not serving yet" list

## Discipline
- Audiences must resolve to concrete scenarios; "all developers" is not an audience.
