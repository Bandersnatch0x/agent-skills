## 何时使用

- 拷问前沿已清空、共识达成,要把共识固化成谱。
- 已有谱需按新裁决增量修订(修订不重开访谈)。
- 不适用:共识未达成 → 回拷问;谱已在手、要做的是拆票 → 走成票。

## 怎么用

1. **探缝**。缝 = 测试要住的公共边界。优先取**既有**缝、取**最高**的缝,缝越少越好(理想 1 条);
   把缝列出来与用户确认是否符合预期——这是本技能**唯一**要问用户的一件事。
2. **合成,不访谈**。只合成已知;发现共识缺口即停,输出缺口清单并指出哪几条该回拷问,
   **不在谱里留待定项**。边合成边把每条断言追溯到来处(票、研究、裁决记录)。
3. **写谱**。必需九节,按序:
   | 节 | 内容 |
   | --- | --- |
   | 状态头 | 三行:谱的落点、门禁命令、权威来源指针 |
   | 问题陈述 | 用户视角的问题 |
   | 方案 | 用户视角的方案 |
   | 用户故事 | 编号列表,句式「作为…,我想要…,以便…」;**要长**,一条一场景 |
   | 实现决策 | 要建的模块、要改的接口、架构决议、数据形态、契约 |
   | 测试决策 | 好测试的判据、缝在哪、哪些模块被测、仓内同类测试先例 |
   | 评审焦点 | 规格沉默但实现仍会遇到的输入或失效模式,逐行「条件 → 理性人期待的行为」,按可能性排序 |
   | 全局约束 | 跨全项目的硬要求**逐字**照抄(版本下限、命名与文案规则、平台要求) |
   | 范围外 | 明确不做的事,一条一行 |
   可选末节「进一步说明」。
4. **自审四查**(自跑,不派代理):①每条裁决能否指到所属节;②待定项扫描(**含「稍后补」「适当处理」这类伪装**)③名称一致性(同一物在两节叫不同名 = 缺陷);④评审焦点每行是否已有测试决策兜住。「空节意味着你查过且没有,不意味着你跳过了检查。」发现即就地修,不重审。
5. **发布**。谱落本仓 tracker 为**议题票**(不落文件),与票据惯例一致:关联源票、写 Log、打「可开工」标记。发布后交给成票,**不自行拆票**。

## 边界

- **不访谈用户**(定义性约束):本技能区别于拷问的就是这一条。唯一例外是第 1 步的缝确认——缝必须事先约定,否则测试力气会散在每个边界情况上。
- **不写文件路径与代码片段**:它们很快过期。例外是原型产出的编码性片段(状态机、数据形态、类型形状),若它比散文更精确地编码了某条决策,内联在该决策下并注明来自原型,且**裁到决策密集处,不是可运行的样例**。
- **不拆票、不关闭也不修改源票**。
- 谱是权威:实现与评审以谱为准;规格沉默处按「一个理性使用该软件的人会期待什么」判,沉默不是许可。
